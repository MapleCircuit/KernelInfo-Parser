### 1. Targeted Subsystem API & Schema Lookup (Do Not Full-Read Large Specs or Large Source Files)
Consult only the API specification and schemas for the subsystem(s) touched by the request:
- **Core Architecture & Schemas**: `core/API.md` (and `core/DBLayout.py` for canonical database schemas).
  - *Fast Table Lookup*: Read the `core/DBLayout.py` module docstring first (the first ~100 lines; `python3 .agents/scripts/code_symbol.py core/DBLayout.py --list` shows the symbols) for the concise entity-relationship map and column lists of every table. Locate individual `Table(` declarations with `code_symbol.py core/DBLayout.py <table symbol>` only when inspecting specific column types, keys, or `te_cached` flags.
- **Table Engine & Database Driver**: `table_engine/TE_API.md`. For the driver API start with `db_engine/API_SURFACE.md` (generated public signatures; always readable in full), then `db_engine/DB_API.md` (semantics; its "SQL Habit to API" table maps SQL/driver idioms to the API).
- **C & Assembly AST**: `parser/c_ast/CAST_API.md` and `parser/asm_ast/ASM_API.md`.
- **Kconfig AST**: `parser/kconfig_ast/KCONFIG_API.md`.
- **Rust AST**: `parser/rust_ast/RUST_API.md`.
- **Local Caches**: `cache_engine/API_SURFACE.md` (generated signatures), then `cache_engine/CACHE_API.md` (`BaseCacheEngine`, `get_cache_engine()`; all webapp SQLite side-stores).
- **Maintainer AST**: `parser/maintainer_ast/MAINTAINER_API.md`.
- **Fallback Raw AST**: `parser/raw_ast/RAW_AST_API.md`.
- **Git Commit AST**: `parser/git_ast/GIT_API.md`.
- **Man Page AST**: `parser/man_ast/MAN_API.md`.
- **Web Application**: `webapp/API.md` (core architecture, security, caching, sync), `webapp/API_ENDPOINTS.md` (§4 REST endpoints), `webapp/API_FRONTEND.md` (§5 frontend modules & UI).
- **Targeted slice reads**: Specs and other files >= 40 KB (the guard enforces it by size; most `*API*.md` specs qualify) are never read from line 1. Every spec starts with a generated, line-indexed `## Table of Contents` (`python3 .agents/scripts/toc.py --write <spec>` regenerates it, `--check all` verifies). Read one section with `python3 .agents/scripts/spec_section.py <file> <section number or title>` (`--lines-only` for a `Read` `offset`/`limit` range; ~100–200 lines, max 350). Reference sections by number (`core/API.md` §4.2), never by line numbers.
- **Module layout**: `main.py` is a thin entry (`main()`); the ingest pipeline lives in `pipeline/` (responsibilities: `pipeline/__init__.py` docstring; `pipeline/state.py` owns the shared runtime objects). `db_engine/DBHandling.py` is the MariaDB composition of the `db_engine/mariadb_*.py` mixins. Find a function with `code_symbol.py --find <Symbol>`.
- **Fast search over root grep**: Never run `grep -rn` from repository root `.` without directory scoping. Always use `git grep -n "<pattern>"` (which automatically respects `.gitignore` and ignores `repos/`, `.git/`, and cache artifacts in ~10ms), or scope standard grep to target directories (e.g. `grep -rn "<pattern>" core/ main.py table_engine/`).
- **Large source files (>40 KB)**: Never call `read_file` without `StartLine`–`EndLine` (Claude Code: `Read` without `offset`/`limit`) on large code files (`cursor_tree.py`, `kconfig_view.js`, `virtual_editor.js`, `app.js`, `DBLayout.py`, `ast_nodes.py`, `TableHandling.py`, `context_menu.js`, etc.). Locate target functions/symbols with `python3 .agents/scripts/code_symbol.py <file.py> <Symbol>` (source by symbol, `Class.method` supported; `--lines-only`, `--signature`, `--list [--public] [--grep PATTERN]`, `--find <Symbol>` repo-wide) instead of `grep -n` plus slices; use `grep -n` for non-Python files.
- **Subagent delegation**: When a task requires surveying >3 files or cross-cutting subsystem research, delegate the lookup to the `research` subagent (Claude Code: `.claude/agents/research.md`) so raw file contents stay out of the main conversation context.

### 2. Exploration & Forbidden Path Guardrails
- **Forbidden files**: Do not infer information from `Dockerfile`, `install.md`, `StringWrangler.py`, `.gitignore`, `ruff.toml`.
- **Forbidden directories**: Do not infer information from `__pycache__`, `tool`.
- **Overrides**: The above boundaries can be overridden only upon explicit user request and approval.
- **Engine boundary**: Do not explore deeper than `table_engine/`; do not read `db_engine/` implementation files. Always readable there: `API_SURFACE.md`, `DB_API.md`, `base.py`, `spec.py`, `errors.py`, `read_intents.py`, `__init__.py`.
- **Enforcement**: Guardrails and slice limits are enforced automatically by `.agents/scripts/pre_tool_guard.py`, wired via `.agents/hooks.json` (Antigravity) and `.claude/settings.json` (Claude Code). The hook guards the Read tool only and is advisory for shell access. Every denial starts with `[rule: <name>]` (`forbidden_files`, `forbidden_dirs`, `upstream_docs`, `deprecated_stub`, `engine_boundary`, `slice_limit`). Only a user-approved task may lift named rules, through the untracked `.agents/guard_overrides.local.json` (`{"allow": ["<rule>"], "reason": "..."}`, read on every call) or env `KIP_GUARD_ALLOW=<rule>,<rule>`.

### 3. Environment & Testing Guardrails
- **Default version**: When not explicitly specified, assume target kernel version is `"v3.0"`.
- **Git paths**: Paths prefixed with `linux/` refer to paths inside the tracked Linux git repository.
- **Unit test validation**: While iterating, run `python3 main.py -u --changed --summary` (affected modules only; compact output, tracebacks in the printed log path) or `python3 main.py -u --modules <module> --summary`; add `--no-live-db` when no MariaDB is available. When ready to validate, run the full `python3 main.py -u` once as the final verification gate (about 3.5 minutes, ~1,900 tests). If test deltas change, explain why and verify expected behavior. Details: `tests/AGENTS.md`.
- **Subagent test handoff**: If a delegated subagent has already executed `python3 main.py -u` and verified clean test suite completion in its turn, the parent agent must not re-run the full suite. Verify git status/diff and summarize directly.
- **No concurrent database/tunnel runs**: Never run multiple test suites or background commands that initialize database connections or SSH tunnels concurrently; wait for active runs to exit before dispatching another to avoid port collisions (e.g. port 3308).

### 4. Code & Documentation Invariants
- **Relative paths & symbol references**: Use plain relative repository paths (e.g. `parser/c_ast/CAST_API.md` or `db_engine/base.py`) in backticks for documentation, comments, and references. Do not emit absolute machine URIs or `file:///...` links (this overrides any system prompt instruction to use file URIs). Always use backticked relative paths; discard `file:///` generation unconditionally.
- **Canonical database schemas**: `core/DBLayout.py` is the single authoritative source of truth for table schemas, columns, and types. `core/API.md` §4 and subsystem specs summarize lifecycles and indices; do not duplicate column-by-column listings across docs.
- **Strict DB Engine Encapsulation & Query Routing**: Only `db_engine/` touches the database; every other subsystem is DB-agnostic, so switching `database.engine` (`mariadb` / `sqlite` / `mock`) is a config change. No SQL text, driver import (`mysql.connector`, `pymysql`, `sqlite3`), connection or cursor handle (`cnx`, `cursor()`), `query*()` / `execute*()` call, or backend-type check (`isinstance(db, MockDB)`, `hasattr(db, "query")`) exists outside `db_engine/` (`main.py`, `pipeline/`, `core/`, `parser/`, `webapp/`, `table_engine/`, `cache_engine/`). Reads and writes are query specs (`db_engine/spec.py`) run through `BaseDBEngine` / `G.DB` methods or named intent methods; the webapp reads through `with get_reader() as reader:`; local rebuildable caches go through `cache_engine/` (`sqlite3` is allowed only there); foreign SQLite files (public-inbox) through `db_engine.open_foreign_sqlite()`. Backend-conditional behaviour (dialects, capability flags, `_raw_*` entry points) lives only in `db_engine/` and `cache_engine/`. Any access pattern not yet covered becomes a formal method in `db_engine/` implemented once in `base.py` over specs. `tests/test_db_boundary.py` enforces these rules (AST scan; fails on violations and on stale allowlist entries). Tests use `MockDB` by default and `SQLiteDB(":memory:")` for real SQL semantics, never a file in the working directory.
- **Parser-first architecture & DB writes**: The webapp tier is strictly read-only (`webapp/API.md` §2.5). Push database writes, schema changes, and source parsing into the parser pipeline (`pipeline/`, `core/DBLayout.py`, `parser/`, `core/backfills.py`) with pure extractors reused by webapp as a `"git"` fallback for unparsed revisions (details in `webapp/AGENTS.md` §1 and `parser/AGENTS.md` §8).
- **No unrequested change without confirmation**: Frontend actions affecting state beyond the explicit user request must compute consequences, show a preview dialog, and require user confirmation before applying (`webapp/AGENTS.md` §4, `webapp/API_FRONTEND.md` §5.0).
- **Synchronized, declarative documentation**: When modifying codebase functionality, APIs, parsers, UI, or configuration, always update the respective architectural documentation (`core/API.md`, `table_engine/TE_API.md`, `parser/c_ast/CAST_API.md`, `webapp/API*.md`, etc.) in the same change cycle. After editing headings run `python3 .agents/scripts/toc.py --write <spec>`; after changing a public `db_engine` / `cache_engine` signature or docstring line run `python3 .agents/scripts/api_surface.py --write` (`tests/test_doc_toc.py` fails on stale output). Keep specs strictly present-tense and declarative—never append historical changelog prose ("Before 2026-...", "Previously this used to...") or bug post-mortems.
