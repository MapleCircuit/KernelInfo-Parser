# Cache Engine API Specification

`cache_engine/` keeps **local, rebuildable caches** (indexes and derived data the webapp computes from Git) behind a
storage-neutral API. It is separate from the main database (`db_engine/DB_API.md`): the webapp never writes the
database (`webapp/API.md` §2.5), and these caches hold derived data that may be dropped at any time and is rebuilt on
demand; whether a cache outlives the process depends on the engine (§5: SQLite files persist, the RAM engine does not).
The public surface speaks in cache terms (spaces, stores, records, keys, conditions, metadata, batches, compaction), so
an implementation that works differently (in-memory, a directory of files, a key-value library) can be added and
selected by configuration without touching a caller.

## 1. Overview, Layout & Configuration

```
cache_engine/
├── __init__.py       # get_cache_engine(), register_cache_engine(), available_cache_engines(), cache_root(); re-exports
├── base.py           # BaseCacheEngine / CacheSpace / CacheStore ABCs, StoreSpec/Field schema, condition objects
├── errors.py         # CacheError and subclasses (no driver exception crosses the engine boundary)
├── sqlite_cache.py   # SQLiteCacheEngine: the only module importing sqlite3
└── ram_cache.py      # RAMCacheEngine: pure-Python in-memory engine
```

- **Factory**: `get_cache_engine(name=None) -> BaseCacheEngine` returns the process-wide instance registered under
  `name` (aliases share it); without `name` the configured engine. `register_cache_engine(name, factory,
  aliases=())` adds an implementation (`factory` is a no-argument callable); `available_cache_engines(*,
  include_aliases=False)` lists names; `configured_engine_name()`. Unknown names raise `UnknownCacheEngine`.
- **Configuration** (`core/config.py` section `cache`): `cache.engine` (default `"ram"`, also `"sqlite"`; environment
  `KERNELINFO_CACHE_ENGINE` overrides) and `cache.dir` (base directory of directory-based engines and scope key of RAM
  spaces; empty: default).
  `cache_root()` resolves the directory on every call: `KERNELINFO_CACHE_DIR`, else `cache.dir`, else
  `~/.cache/kernelinfo`. The gzip-JSON `DiskCache` (`webapp/API.md` §2.14) shares the same root. The cache works
  without the application config (a missing config means the defaults).
- **Scope**: query-shaped record stores (keyed or keyless records, secondary lookups, ranges, aggregates) use
  `cache_engine`. The whole-document blob caches of the webapp (`webapp/backend/services/disk_cache.py`,
  `webapp/API.md` §2.14) are a documented exemption: they need guaranteed persistence across restarts, a global LRU
  byte cap and cheap large blobs, which the record-store API does not promise.
- **Layout**: a space is addressed by `namespace` (`[a-z0-9][a-z0-9._-]{0,63}`, e.g. `commit-relations`) and `name`
  (free text, sanitised by the engine; callers put the repository and a format version in it, e.g. `linux-v2`).

## 2. Data Model: Spaces, Stores, Records, Schema

- **Space** (`CacheSpace`): a named group of stores that share storage, lifetime, metadata and transactions; one
  `engine.open(namespace, name, stores)`. It is the unit of invalidation, maintenance and atomic multi-store writes.
- **Store** (`CacheStore`): one declared set of records inside a space.
- **Record**: a tuple of field values in `StoreSpec.fields` order. Values are `int`, `float`, `str`, `bytes` or `None`
  (nullable fields only).
- **Key**: the value of the single key field, or a tuple of the key fields in `StoreSpec.key` order.
- **Schema** (own neutral types; not coupled to `db_engine`): `FieldType` (`INT`, `FLOAT`, `TEXT`, `BYTES`);
  `Field(name, type, nullable=False)` with constructors `INT(name, null=False)`, `FLOAT`, `TEXT`, `BYTES`;
  `StoreSpec(name, fields, key=(), unique=(), indexes=(), clustered=False)`:
  - `key`: unique record identity; empty for a keyless store (an insertion-ordered set, deduplicated by `unique`).
  - `unique`: further unique field groups. Groups containing nullable fields use the engine's NULL semantics (SQLite:
    NULLs never collide), so callers do not rely on them for deduplication.
  - `indexes`: lookup hints (results never depend on them; engines may ignore them).
  - `clustered`: hint to store records in key order (needs a key).
  Names match `[a-z][a-z0-9_]*`; the store name `meta` is reserved (space metadata).
- **Conditions** (`where`, all must hold): `Eq(field, value)` (`None` means IS NULL), `In(field, values)`,
  `Range(field, ge=, gt=, le=, lt=)`, `Prefix(field, value)` (text or bytes), `IsNull(field, negate=False)`. `where`
  may be one condition, a sequence of them, or a mapping `{field: value}` (`None` = IS NULL, list/tuple/set = IN).
- **Metadata**: string key/value stamps of the space (build time, covered heads, format), used as freshness markers.

## 3. Operations (`CacheStore`, `CacheSpace`, `BaseCacheEngine`)

`BaseCacheEngine`:
- `open(namespace, name, stores: Sequence[StoreSpec]) -> CacheSpace`: opens, creating when absent. Opening the same
  space again returns the same handle (cheap; services call it per use, which also follows a changed cache root or
  active repository). The same space opened with another schema, or a stored schema that differs from `stores`, raises
  `CacheSchemaError`: version the space `name` to change a schema (a new name is a rebuild; the storage held under the
  old name stays until it is discarded).
- `exists(namespace, name) -> bool` (without creating), `location(namespace, name) -> str`, `close()` (all spaces).

`CacheSpace`:
- `store(name) -> CacheStore`.
- `get_meta(key) -> str | None`, `set_meta(key, value)`, `delete_meta(key)`.
- `batch()`: context manager; the calls inside (any stores, metadata) are atomic and invisible to other threads until
  the outermost block ends; re-entrant; an exception rolls everything back. A batch whose space handle is closed before
  the outermost block ends raises `CacheError` and writes nothing; a reopened handle is unaffected.
- `clear()`: delete every record and all metadata (schema stays). `discard()`: delete the storage and close the handle
  (a corrupt or obsolete cache). `compact()`: maintenance, never changes content. `size_bytes()` (an engine-defined
  size: bytes on disk for SQLite, an estimate for RAM, §5.2), `close()`, `location` (display only).

`CacheStore` (each call atomic and thread-safe):
- `get(key) -> Record | None`; `get_many(keys) -> {key: Record}` (any number of keys, absent ones omitted).
- `put(record)`; `put_many(records, *, replace=True) -> int`: bulk, one atomic call, `records` may be a generator;
  `replace=True` inserts or replaces, `False` skips records colliding on the key or a unique group; returns the
  number written. A record that does not fit (arity, a null in a non-nullable field, a value the engine cannot store
  or index) fails the whole call with a `CacheError` and nothing of the call is written.
- `delete(key) -> bool`, `delete_many(keys) -> int`, `delete_where(where) -> int` (empty `where`: all), `clear()`.
- `update_where(where, values: Mapping[str, Any]) -> int` (key fields cannot be updated).
- `scan(where=None, *, columns=None, order_by=(), limit=None) -> Iterator[tuple]`: matching records, or the projected
  `columns`; `order_by` names fields, a leading `-` for descending. Without `order_by` the order is unspecified except
  that a keyless store yields insertion order. Streams in batches.
- `count(where=None)`, `sum(field, where=None)` (0 when empty), `max(field, where=None)` (None when empty).
- Large `In` lists are split by the engine transparently for `get_many`, `delete_many`, `scan`, `count`, `sum`,
  `max`, `delete_where` and `update_where`; a `scan` that also has `order_by`/`limit` (or two long `In` lists) raises
  `CacheSchemaError`.
- Bulk work stays bulk: callers hand whole batches to `put_many`/`get_many` instead of looping single calls.

## 4. Errors

All in `cache_engine/errors.py`, exported from `cache_engine`; callers catch `CacheError` (a failed cache is skipped
or rebuilt, never fatal).
- `CacheError`: base. `CacheUnavailableError`: cannot open/create the storage (permissions, disk). `CacheBusyError`:
  locked beyond the timeout. `CacheCorruptError`: unreadable data (`space.discard()` and rebuild).
  `CacheSchemaError(CacheError, ValueError)`: bad declaration, field, condition or record arity, or a schema mismatch.
  `UnknownCacheEngine(CacheError, KeyError)`.
- Driver exceptions (`sqlite3.Error`, `OSError`) are translated inside the engine.

## 5. Built-in Engines

### 5.1. SQLite Engine

`SQLiteCacheEngine(root=None)` (`cache.engine = "sqlite"`, aliases `sqlite3`). Every `import sqlite3` of the cache
lives in `cache_engine/sqlite_cache.py`.
- **Files**: `<cache root>/<namespace>/<name>.sqlite3`, WAL journal, `synchronous=NORMAL`, 60 s busy timeout. A store is
  a table of the same name with typed columns (`INT`→INTEGER, `FLOAT`→REAL, `TEXT`, `BYTES`→BLOB), indexes named
  `<store>_<fields>`, `clustered` → `WITHOUT ROWID`; space metadata is the table `meta (key TEXT PRIMARY KEY, value
  TEXT)`. `CREATE ... IF NOT EXISTS` plus a column-name check on open make files written before the cache engine
  existed (commit relations, release index, fact stores) open unchanged.
- **Concurrency**: one connection per thread (concurrent readers under WAL), one re-entrant write lock per space
  (writes and `batch()` are serialised, a batch holds the lock), `BEGIN IMMEDIATE` for writes so other processes
  serialise through SQLite. `scan` streams through the calling thread's connection.
- **Maintenance**: `compact()` is `PRAGMA wal_checkpoint(TRUNCATE)`. `discard()` removes the file and its `-wal`/`-shm`.
- **Keyless stores** scan `ORDER BY rowid` (insertion order); keys, `put_many(replace=False)` and unique groups map to
  `INSERT OR IGNORE` / `OR REPLACE`.
- The engine does not bound its size; callers prune (`FactStore.prune`) or version the space.

### 5.2. RAM Engine

`RAMCacheEngine(root=None)` (`cache.engine = "ram"`, aliases `memory`, `mem`, `in-memory`, `in_memory`). Pure-Python
in-memory implementation in `cache_engine/ram_cache.py` (stdlib only, no `sqlite3` or C extensions).
- **Durability and footprint**: nothing survives process exit. Every restart, including each `uvicorn --reload`
  restart, rebuilds the spaces on first use, and each process (every worker of a multi-process server, the parser,
  a test run) holds its own copy. The engine does not bound memory: the callers' `max_mb` settings cap the payload
  they hand over, not the engine's dict, index and object overhead.
- **Lifecycle**: each engine instance owns process-local `_backing` storage keyed by `(scope, namespace, name)` and
  open `_spaces` handles (`scope` is `root` if given, else resolved via `cache_root()` on every `open()`/`exists()` so
  changing `KERNELINFO_CACHE_DIR` or `cache.dir` isolates spaces); `location()` returns `ram://<namespace>/<name>`.
  `space.close()` marks the handle closed while keeping `_backing` intact so `exists()` stays `True` and `open()`
  returns a new handle; `space.discard()` removes `_backing` so `exists()` becomes `False`.
  `discard_scope(root) -> int` closes and drops every space held under one cache root (tests release their temporary
  scope with it).
- **Data structures & query planner**: keyed stores store records in `dict[Key, Record]` (keyless stores in
  insertion-ordered `dict[int, Record]`), `unique` groups in per-group `dict`s (NULLs do not collide), `indexes` (plus
  leading key fields of composite keys) as inline-1-or-set hash indexes, and lazy chunked `_SortedIndex`es built on
  first `Range`, `Prefix`, or `order_by` query. The `clustered` hint is ignored. Without `order_by`, a keyless store
  yields matches in row-id (insertion) order on every access path. `compact()` shrinks dicts/sets and rebalances
  sparse sorted chunks; `size_bytes()` is an O(1) estimate of per-row record and index overhead from row counts that
  ignores value sizes (`0` when empty), not a measured memory footprint.
- **Values**: fields are not type-checked. Key, unique and indexed field values are checked for hashability before a
  `put_many` or `update_where` applies anything. Values that cannot be ordered together (mixed types in one field, or
  a bound of another type) make a `Range`, `Prefix`, `order_by`, `sum` or `max` raise `CacheSchemaError`; a write never
  fails on them: a lazy sorted index that meets them is dropped and rebuilt by the next query.
- **Concurrency & `batch()`**: two re-entrant locks live on the shared space storage, so every handle of a space
  (a closed one and its reopened successor) serialises on the same locks. The write lock serialises writers and
  `batch()` holders. The commit lock guards committed-state swaps, in-place writes and reader pin counters: `get`, `get_many`,
  `count`, `sum`, `max` and metadata reads run under it without pinning `readers`; `scan` pins the committed state
  (`readers += 1` under the commit lock) and reads it without the lock, and a writer that finds `readers > 0`
  copies the state (copy-on-write; the lazy sorted-index map is snapshotted under the commit lock) instead of
  changing it in place. A `scan` iterator keeps its snapshot until exhausted, closed or collected; a finalizer
  that cannot take the commit lock without blocking queues the release for the next locked operation.
  Re-entrant `batch()` writes to an isolated working state or an O(delta) `_KeyedDelta` / `_KeylessDelta` overlay
  (large simple keyed stores and keyless stores); when `readers == 0` on outermost exit, `_KeylessDelta` mutates
  the base state in place under the commit lock, otherwise it builds every new state before swapping any in.

## 6. Adding an Engine & Contract Tests

1. Subclass `BaseCacheEngine` (spaces implement `CacheSpace`, stores `CacheStore`), translate every backend failure to a
   `CacheError` subclass, and honour the semantics of §3 (including atomic `batch()` and thread safety).
2. `register_cache_engine("name", Factory, aliases=())` at import of the module (and import it from
   `cache_engine/__init__.py`), then select it with `cache.engine`.
3. Reuse `unit_test/test_cache_engine.py::CacheEngineContract`: a mixin that runs the full behavioural suite against
   `make_engine(root)`; subclass it with `unittest.TestCase`. Engine-specific tests (file layout, legacy files) live in
   the engine's own test class.

Access patterns served: key lookups (`get`/`get_many`, composite keys), secondary lookups by field equality or IN
(`rel` by `src`/`dst`/`p8`, `links` by `sha`/`mid`), key-range lookups (`first_tag` by hash prefix), bulk insert-if-absent
batches inside a `batch()` (build passes), bulk replace per revision/tag, freshness markers (metadata), full
invalidation (`clear()`), LRU pruning (`scan(order_by=("used",), limit=...)` + `delete_many` + `compact()`),
aggregates (`count`, `sum`, `max`).
